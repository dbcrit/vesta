# deploy/

| Path | What |
|---|---|
| `helm/vesta/` | Helm chart: vesta-agent DaemonSet with the vesta-install init container, RuntimeClass `kata-qemu-vesta`, RBAC, ValidatingAdmissionPolicy, ConfigMaps. See [helm/vesta/README.md](helm/vesta/README.md). |
| `helm/vesta/files/seccomp/` | vesta-agent Localhost seccomp profiles, generated by `hack/gen-seccomp-profile.sh` (`make seccomp`). |
| `manifests/` | Plain manifests: `vesta.yaml` is `helm template` output with default values (`make helm`; CI fails if stale), plus the namespace. Install with `kubectl apply -k deploy/manifests`. |

Behaviour of the chart:

- **DaemonSet placement:** it runs only on nodes labelled `katacontainers.io/kata-runtime=true`, the label kata-deploy sets. The selector is configurable.
- **RuntimeClass:** `kata-qemu-vesta` has `handler: kata-qemu-vesta` and `scheduling.nodeSelector: {vesta.dev/guest-ready: <guestVersion>}`. Its pod overhead is 352Mi/250m, which is kata-deploy's 320Mi for `qemu-runtime-rs` plus room for guestd and resident BTF.
- **vesta-agent:** it runs with `hostNetwork: true` and mounts `/var/run/nri`, `/run/kata` and `/run/vc/sbs` read-only (it connects to Unix sockets there).
